## 已确认的原问题与修复

- 报表权限默认集合和数据库覆盖曾给超管租户业务权。新增角色级拒绝优先于覆盖；平台操作身份与后台 `tenant_id=0,user_id=0` 分开。
- 原 `data_masker.check_rate_limit` 使用进程内字典；现门面为异步共享服务，聊天、流式、实时钻取及非 API SQL 路径统一接入，重试不重复计数。报表作业预算仍由独立报表配额控制。
- 原知识治理超管分支直接允许所有范围；标签查询接受 `include_all_private`。现共享治理与 RLS 双重隔离，旧开关不再生效，普通知识检索不携带应急授权。
- 新增回归复现 MCP 缓存仅按显示名称和优先级解析，可能选中其他身份已加载的私有连接。现解析和实际调用均校验身份；连接被删除、停用、改址或安全阻断后，缓存工具不得继续请求远端。
- 新迁移 `023_query_quota.sql` 和 `024_platform_tenant_boundaries.sql` 追加升级；未改已执行的历史迁移校验和，未在用户业务数据库执行。

## 操作入口

- 租户管理员：管理工作区 → 查询额度；知识库 → 应急授权（只能授权可管理的单个文件）。
- 平台超管：管理工作区 → MCP 安全停用；知识库 → 应急授权（输入受让授权 ID 显式下载）。
- 应急授权不包含批量导出、写权限、搜索、标签或其他文件。私有知识不能由租户管理员代拥有者授权。
- 私有标签提升旧入口返回 410；平台只能独立创建全局标签。
- 存量超管报表保留数据库记录，但不自动改所有者、不自动授给任何租户。

## 计数语义

报表次数仍是 `Asia/Shanghai` 自然月，不是“本周”。本次新增的查询频率是另一项资源：数据库 UTC 自然小时窗口。
`max_queries_per_hour` 作为平台硬上限，租户配置须满足 `0 <= user_per_hour <= tenant_per_hour <= hard_limit`。
拒绝请求不扣减，数据库失败不回退本地放行；平台降低硬上限后，旧软配置在运行时被截断。
