### 合并验收边界

本轮最终验收结果如下。浏览器使用隔离 Vite 与拦截的业务请求；搜索和模型测试使用真实模块逻辑与 Fake MCP/Fake LLM，不代表生产部署验收。

| 验证 | 结果 | 范围与限制 |
|---|---|---|
| 主线组合回归 | 1026 通过、4 跳过、2 排除 | 46 个本轮变更及相邻测试文件；3 项跳过为 Windows 符号链接能力限制，浏览器项另行显式执行；2 项排除为下述已确认基线错误 |
| SQL/技能/MCP/双语外部独立验收 | 57 通过、1 跳过 | 含真实本地 stdio；跳过项依赖当前环境不可用的符号链接能力 |
| 搜索外部独立验收 | 45 通过 | 误授权、否定优先、能力咨询、任意前缀、合法主题保留、响应预算与脱敏 |
| 搜索及相邻模块独立回归 | 381 通过 | 搜索、研究子图、Prompt 与架构约束 |
| 图表合并真实浏览器验收 | 1 通过 | 显式启用浏览器；确认前后切换图表类型的请求与页面状态 |
| 前端构建 | 通过 | TypeScript 检查及 Vite 生产构建 |

组合回归发现两项基线配置测试使用 `logging.extra` 的保留键 `name`，在前序日志测试将 INFO 打开后抛出 `KeyError`。已用 `244da1b` 的原始测试源码重放同一异常，并确认原测试类与当前 AST 完全一致；这两项不是本轮实现引入，最终有效回归显式排除并保留该限制说明。另有 `src/api/routes/__init__.py` 的既存 Ruff `I001` 导入排序提示，基线源码同样复现；其余改动文件的 Ruff 与全部改动 Python 文件的语法检查通过。

[^5]: **4.3.2/4.3.5/4.3.6 Schema 关键词+向量检索/业务规则/历史模板** — 原因: 依赖模块 6 (知识库 ChromaDB) 和模块 7 (长期记忆 Core) 未实现。条件: SchemaManager + BusinessRuleStore + LongTermMemoryStore 就绪。时机: Phase 2 (模块 6/7 完成后)。
